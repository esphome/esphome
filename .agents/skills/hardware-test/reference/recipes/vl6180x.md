# VL6180X range and light sensor (#22689)

`scripts/vl6180x/`, for an ESP8266 NodeMCU with the breakout on SDA GPIO4, SCL GPIO5, GPIO0/CE (XSHUT) on GPIO14 and
GPIO1/INT on GPIO12:
- `vlprobe.yaml`: bus scan plus raw reads of MODEL_ID 0x000 (0xB4), MODEL_REV_MAJOR and FRESH_OUT_OF_RESET, with
  XSHUT driven high first.
- `gen.py NAME SCALER GAIN IT_MS PINS [extra yaml...]`: one config per variant (SCALER 0 = illuminance only, PINS 1 =
  `enable_pin: GPIO14`). Extras: `extra_regs.yaml` logs offset, scaling, ALS gain, ALS status and
  `status_has_warning()` every 10 s (it opens `interval:`, so list it first); `extra_xshut.yaml` pulls XSHUT low for
  50 ms at 25 s; `ei_ext.yaml` with `ei_nt_ovf.yaml` or `ei_fail_ovf.yaml` drive the injection hook below.
- `run.sh NAME YAML PORT SECONDS`: build, flash, capture from a reset, `ana.py` summary (counts, median, NaN,
  warnings). `phase.py CAPTURE` counts publishes and core `set/cleared Warning flag` lines per injection window
  (logged only on a change).

Facts:
- A target closer than the sensor's minimum or ALS overflow may never happen on the bench. Force them with a test hook
  in a local copy of the component under `ext/components/vl6180x`: globals `bool vl_inject_no_target`,
  `vl_inject_als_overflow`, `vl_inject_als_fail` defined before the namespace and declared `extern` in the header,
  `status[0] = 0xB1` (range error 11) or `result[0] = 0x11` (ALS error 1) before the error checks, and
  `!::vl_inject_als_fail && read_register16(REG_RESULT_ALS_STATUS...)` for a read failure; the ei files toggle them.
- The breakout keeps XSHUT high when the pin floats, so without `enable_pin` the sensor keeps power across ESP resets
  (FRESH_OUT_OF_RESET stays 0). The factory part to part offset read 7.
- An XSHUT pulse resets the sensor to defaults (FRESH_OUT_OF_RESET 1, ALS gain register 0x06, scaling 0x0107); the
  component then sets the comm warning and stops publishing until a reboot (the vl53l0x pattern).
- Sensor publish lines are VERBOSE (`'X' >> value`); set `logs: sensor: VERBOSE` to count readings.
- With 25 failing updates the final #22689 head logged 1 warning set and 1 clear; an earlier head logged 25 and 24.
- Two hubs where the second one's enable pin (GPIO13) is not wired: the first re-addresses to 0x31 and reads, the second
  is marked failed.
