The `cse7761` sensor platform allows you to use your CSE7761 voltage/current and power sensors
with ESPHome. This sensor is commonly found in Sonoff Dual R3 v1.x.

> [!NOTE]
> SAFETY HAZARD: Some devices such as Sonoff POWs/Shelly/etc, have the digital GND connected directly to mains voltage so **the GPIOs become LIVE during normal operation**. Our advice is to mark these boards to prevent any use of the dangerous digital pins.

As the communication with the CSE7761 done using UART, you need
to have an [UART bus](/components/uart) in your configuration with the `tx_pin` and `rx_pin` connected to the CSE7761.
Additionally, you need to set the baud rate to 38400 and parity to `EVEN`.

```yaml
# Example configuration entry
sensor:
  - platform: cse7761
    voltage:
      name: 'CSE7761 Voltage'
    current_1:
      name: 'CSE7761 Current 1'
    current_2:
      name: 'CSE7761 Current 2'
    active_power_1:
      name: 'CSE7761 Active Power 1'
    active_power_2:
      name: 'CSE7761 Active Power 2'
    energy_1:
      name: 'CSE7761 Energy 1'
    energy_2:
      name: 'CSE7761 Energy 2'
    frequency:
      name: 'CSE7761 Frequency'
    power_factor_1:
      name: 'CSE7761 Power Factor 1'
```

> [!NOTE]
> The configuration above should work for Sonoff Dual R3 v1.x.

## Configuration variables

- **voltage** (*Optional*): Use the voltage value of the sensor in V (RMS).
  All options from [Sensor](/components/sensor).

- **current_1** (*Optional*): Use the current value of the channel 1 in amperes. All options from
  [Sensor](/components/sensor).

- **current_2** (*Optional*): Use the current value of the channel 2 in amperes. All options from
  [Sensor](/components/sensor).

- **active_power_1** (*Optional*): Use the (active) power value of the channel 1 in watts. All options from
  [Sensor](/components/sensor).

- **active_power_2** (*Optional*): Use the (active) power value of the channel 2 in watts. All options from
  [Sensor](/components/sensor).

- **energy_1** (*Optional*): Use the active energy counted by channel 1 in watt-hours. All options from
  [Sensor](/components/sensor/).

- **energy_2** (*Optional*): Use the active energy counted by channel 2 in watt-hours. All options from
  [Sensor](/components/sensor/).

- **frequency** (*Optional*): Use the mains frequency in Hz. All options from
  [Sensor](/components/sensor/).

- **power_factor_1** (*Optional*): Use the power factor of channel 1. The chip reports it for channel 1 only.
  All options from [Sensor](/components/sensor/).

- **update_interval** (*Optional*, [Time](/guides/configuration-types#time)): The interval to check the
  sensor. Defaults to `60s`.

- **uart_id** (*Optional*, [ID](/guides/configuration-types#id)): Manually specify the ID of the [UART Component](/components/uart) if you want
  to use multiple UART buses.

The energy values come from the chip's pulse counters and start from zero again after a reboot. Home Assistant's
energy dashboard handles that reset because the sensors use `total_increasing`; for a daily total that survives
reboots, feed `active_power_1` or `active_power_2` into the [Total Daily Energy](/components/sensor/total_daily_energy/)
sensor.
